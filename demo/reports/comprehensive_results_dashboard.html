What is InterVul-Graph? (From Day 1 to Now)

In modern software security, traditional deep learning vulnerability scanners (like CodeBERT, VulDeePecker, or Devign) analyze one single C/C++ function in total isolation. However, real software security vulnerabilities almost never live in isolation:

  • An input originates from an untrusted network buffer or file in a caller function (Source).
  • It passes through intermediary processing functions (Intermediate).
  • It finally crashes or executes commands in a dangerous memory copy or command invocation (Sink).
❌ Isolated Function Analysis (Baseline) High Errors

The model sees only the target function body. It has zero knowledge of where variables came from or where they go.

  • False Positives: Flags safe pointer arithmetic because it cannot see that the caller already checked length < MAX_BOUND.
  • False Negatives: Misses dangerous operations because the actual vulnerable system() call happens inside a delegated callee function.
✅ InterVul-Graph (Our Approach) +4.7% F1 Gain

Extracts the C/C++ AST Call-Graph using Tree-sitter and feeds interprocedural context (Caller + Target + Callee) into the model.

  • Suppresses False Alarms: Sees sanitizers and validation bounds in upstream callers.
  • Catches Hidden Bugs: Tracks dangerous calls (e.g. strcpy, system) in downstream callees.
  • Visual Chain: Connects Source → Target → Sink so developers understand the bug path.
End-to-End Pipeline Summary
We built a complete, reproducible system: (1) Dataset acquisition & bipartite leakage clustering → (2) Tree-sitter C/C++ AST parser & call-graph builder → (3) Fine-tuned CodeBERT on GPU (FP16 mixed precision) → (4) Interprocedural context strategies (Local, Caller, Callee, Full) → (5) Vulnerability chain detector (Source → Target → Sink) → (6) Multi-format visual reporting (HTML, SVG, Terminal ASCII, Flask Web App).

Model Architecture: Did We Train or Use Pretrained?

A critical question for any university review is: "Did you train the model from scratch, or did you use a pre-trained model from Hugging Face?"

The Exact Academic Truth

We followed the standard state-of-the-art methodology in ML research: Transfer Learning (Pre-training + Task-Specific Fine-Tuning).

  1. Pre-trained Foundation: We started from microsoft/codebert-base (and microsoft/graphcodebert-base) downloaded from Hugging Face. These foundation models were pre-trained by Microsoft on 6.4 million code functions from GitHub to understand general C, C++, and Python syntax.
  2. Custom Security Classification Head: We initialized a custom 2-class linear classifier on top of the 768-dimensional [CLS] representation:
    Input Code → CodeBERT Transformer (12 layers, 125M params) → Pooler → Dropout(0.1) → Linear(768 → 2) → Softmax
  3. Local GPU Fine-Tuning: We fine-tuned the entire model end-to-end on our curated C/C++ security vulnerability dataset using your local NVIDIA GeForce RTX 3050 Laptop GPU using PyTorch and FP16 mixed precision.
  4. Checkpoint Artifact: The resulting learned security weights are stored locally in: models/codebert/pytorch_model.bin and models/codebert/config.json.

Key Statistical Findings
  • The Full Context Advantage: Providing bidirectional caller and callee context boosts CodeBERT F1 by +4.7% (0.6798 → 0.7268) and ROC-AUC by +5.2% (0.7410 → 0.7930).
  • Caller vs Callee Roles:
    • Caller context primarily boosts Precision (+3.1%) because upstream sanitizers help dismiss false alarms.
    • Callee context primarily boosts Recall (+2.8%) because downstream dangerous API calls help catch hidden sinks.
  • GraphCodeBERT Benefit: GraphCodeBERT achieves ~2% higher baseline and full-context performance because its internal data-flow graph (DFG) edges track variable reachability better than sequential CodeBERT.

Research Insight: F1 Generalization Gap

When standard isolated models are evaluated across different software suites, performance drops drastically by -15.5% F1 (-0.1055). This proves that isolated token embeddings overfit to surface-level coding styles of their training repositories. In contrast, interprocedural full context narrows this generalization drop to -10.2% (-0.0758), preserving significantly more detection fidelity under domain shift.

2. The 5-Minute Presentation Script for Sir

Minute 1: The Problem Hook
"Good morning Sir. Traditional deep learning tools look at a single C function in isolation. But in reality, vulnerabilities are multi-step chains: untrusted input enters in a caller function, passes through helpers, and crashes in a callee sink. In our research, we built InterVul-Graph to test if providing caller/callee context helps CodeBERT detect vulnerabilities better."
Minute 2: The Training & Leakage Defense
"Sir, to ensure scientific rigor, we did not use random splitting. Standard random splits leak functions from the same project into both train and test, causing artificial 90%+ scores. We applied bipartite connected-component clustering across DiverseVul so that our test set contains 0% overlapping projects and 0% overlapping CVEs. We fine-tuned CodeBERT on our local NVIDIA RTX 3050 GPU using FP16 mixed precision."
Minute 3: Show the Live Demo
"Let me run our demonstration script live. Notice how it parses the AST using Tree-sitter and traces the chain: from untrusted process_request down to execute_query and finally reaching system(). It classifies the vulnerability with 0.99 confidence and generates this interactive vector graph."
Minute 4: Show the Empirical Comparison
"Here is our core research finding in the table: On isolated functions, CodeBERT achieves 0.6798 F1. But when we provide full caller and callee context, the F1 jumps to 0.7268 (+4.7% gain), and ROC-AUC reaches 0.7930 (+5.2% gain). Caller context removes false positives by showing input sanitizers, while callee context catches hidden sinks."

3. Anticipated Questions from Sir & Winning Answers

Q1: "Did you train this model from scratch or just download it?"
Answer: "Sir, we used transfer learning. We initialized from Microsoft's pre-trained CodeBERT-base checkpoint from Hugging Face so the model already understood token semantics. Then, we designed a custom classification head and fine-tuned all 125 million parameters on our leak-free C/C++ security vulnerability dataset using PyTorch on our local GPU."
Q2: "Is your chain detection sound static taint analysis?"
Answer: "No, Sir. We are explicit in our report: formal static taint analysis requires compiler IR (like LLVM) and path reachability solvers. What we built is a Tree-sitter AST call-graph extractor with neural node scoring. It computes heuristic chain risk scores to guide human code auditors, rather than claiming mathematical soundness."
Q3: "Why did you test on CVEfixes if you trained on DiverseVul?"
Answer: "To test cross-dataset generalization, Sir. If a model only works on the dataset it was trained on, it has memorized dataset quirks. By freezing the model and testing on CVEfixes, we proved that domain shift drops isolated models by -15.5% F1, proving the necessity of structural interprocedural representations."
Q4: "What is the difference between CodeBERT and GraphCodeBERT in your tests?"
Answer: "CodeBERT only treats code as sequential tokens (like NLP). GraphCodeBERT incorporates an internal data-flow graph (DFG) tracking variable assignment edges. In our experiments, GraphCodeBERT scored ~2% higher (F1 0.7442) because it tracks variable flows across lines more naturally."
